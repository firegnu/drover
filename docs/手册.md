# drover 手册

装和跑看 [QUICKSTART](QUICKSTART.md)。每条命令的参数和退出码看 `drover --help` / `drover board --help`。

**这份文档讲那两处放不下的东西**：为什么这么设计、出事了怎么查、什么时候该停掉它。设计的完整推导在 [ROADMAP](ROADMAP.md)，这里只给用得上的那一层。

---

## 1. 它在哪一层

```
corral              基础设施：开 agent、送话、看状态。不认识任何流程
  ↑
corral-dispatch     内循环：一件活怎么拆、派给谁、怎么审、怎么收尾。主控在场，分钟到小时
  ↑
drover              外循环：队列、闸门、什么时候叫醒。天级，无人值守
```

**依赖只能往下。** drover 用到的 corral 命令只有三个：`send`、`status`、`ls`。它对内循环的依赖薄到——**内循环全靠人手工做的项目，drover 照样能跑**。

它只做两个动作：

1. 往主控送一句话（任务正文）
2. 只读核对 git，判断这件活做完没有

送出去的就是任务正文本身，和你手动粘一段进去一模一样。**主控甚至不需要知道有 drover 这个东西**——送出去的文本里连 `drover` 这个词都不许出现，有测试守着。

它**不**做：不开、不关、不接入任何 agent；不解析主控写的任何自然语言结论；不读 corral 的内部文件；对目标仓库全程只读。

> 这条随时可以真跑来验：**拆掉 drover，目标项目照常工作。**

## 2. 怎么判断「这件活完了」

这是整套东西的地基，值得读完。

### 门 vs 依据

- **门**：现在是不是一个「可以去判断」的时刻。便宜、可观察，只决定**什么时候问**。
- **依据**：凭什么说这件活完了。**只有一个**。

三个**门**（都是纯 git 和 `corral status`，便宜）：

1. `main` 前进了（送任务时记下的 sha 变了）
2. `BRANCH_GLOB` 匹配到的里程碑分支都已经是 `main` 的祖先
3. 验收命令退出码 0

**依据只有一条**：`base_sha..main` 区间里出现了一条**收尾记号**——主控收尾时打的空提交，首行是 `<前缀>: 一句话`。

### 为什么不能用别的信号

试过三个，每个都被真实工作流打穿：

| 提过的信号 | 反例 |
|---|---|
| 主控 idle 了 | 主控派完活就 idle，等子 agent 干几小时。**idle 占一件活的绝大部分时间，而且正是它最忙的时候** |
| 验收命令退出码 0 | 不是所有任务写得出验收命令；写了也只证明没坏，证明不了「要的三件事都做了」 |
| 派出去的 agent 消失 | 主控自己干 → 全程 0 个；主控让已开着的 agent 接着做下一件 → 它们根本不消失 |

**这个模式本身就是结论**：工作流是故意灵活的，任何固定代理信号都有反例。所以 drover 不猜，只认人和主控一起做出的那个判断留下的**痕迹**。

### 四道闸

drover 认收尾记号时要同时满足：

1. **区间**：只在 `base_sha..main` 里找。上一件活的记号进不来
2. **父提交恰好一个**：`git rev-list --parents -n1 <sha>` 恰好两个词
3. **空提交**：`git diff-tree --no-commit-id --name-only -r <sha>` 输出为空
4. **前缀**：首行 `^<DONE_MARK>` 加冒号（全角半角都收）

> 第 2 道不是锦上添花：**合并提交在 `git diff-tree` 眼里输出也是 0 行**（不给 `-m`/`-c` 时 git 对合并提交默认不出 diff）。主控哪天在合并摘要里恰好写了前缀开头，光靠「空 + 前缀」就会误判。

### 失败方向是安全的

```
主控漏打记号  →  drover 看不到完成  →  卡住、挂「等你」   ← 假阴性，你一眼看得出，按一下 g 就过去
绝不会        →  drover 以为完了    →  误发下一件         ← 假阳性
```

**这条约定不可能造成「没做完却判成做完了」**，只可能造成「做完了但还在等你点头」。全自动和人工推进两种模式因此能共用同一套机制，区别只在记号没出现时谁来兜底。

而且还有第二层网：corral-dispatch 第 1 节要求「派新活之前先确认上一件已经收尾，没收尾不派新活」——**就算 drover 误判提前发了，主控自己也会挡一道**。

### 最弱的配置长什么样

`BRANCH_GLOB` 和 `CHECK_CMD` 都留空时，三道门只剩「`main` 前进了」。这时**光靠门谁都骗得过**——主控提一行注释就满足了。所以引擎**见不到收尾记号就绝不自动记 done**，`DONE_MARK` 留空（项目不用记号）也一样，退回等你按 `g`。

手动 `drover done` 是另一回事：**它照样放行**，只把「我没认出完成」说清楚（`✗ 依据 收尾记号：…` 加一句「这次算你自己判断的」）。完成本来就是人的判断，drover 没资格拦人。

## 3. 三档模式

两个开关叠起来，**默认全关**：

| `loop` 文件 | `TASK_GATE` | 行为 | 什么时候用 |
|---|---|---|---|
| 没有 | — | 什么都不自动 | 默认；手动走流程 |
| 有 | 1 | 自动核对判据、自动记 done，下一件等 `g` | **第一次用就选这个** |
| 有 | 0 | 全自动 | 跑顺了之后 |

**开关不是引擎。** `drover loop on` 只是在交接目录里放一个 `loop` 文件，告诉引擎「这个项目要转」。真正推动的是常驻的 `drover loop` 进程；引擎没跑，开关开着也不会动。

引擎一跳做两件事：推一次外层循环（`loop_tick`），以及隔够 60 秒再看一眼有没有新的「等你」要通知。

## 4. 配置

`<项目>/.drover.conf`，一行一个 `键=值`，`#` 开头是注释，不进 git。

| 键 | 作用 | 留空会怎样 |
|---|---|---|
| `HANDOFF_DIR` | 交接目录，`queue.md` 和 `tasks.state` 都在这里 | 报错，这个仓库没接上 |
| `MAIN_AGENT` | 主控在 `corral ls` 里的名字 | 不自动送，`drover next` 把正文打出来让你粘 |
| `BRANCH_GLOB` | 里程碑分支的匹配模式，直接交给 `git branch --list` | 门 2 标「不适用」，不算过也不算不过 |
| `CHECK_CMD` | 默认验收命令 | 门 3 标「不适用」 |
| `DONE_MARK` | 收尾记号的前缀（默认 `收尾`） | 判不出完成，循环不自动记 done |
| `TASK_GATE` | `1` 放行模式（默认）/ `0` 自动模式 | 同 `1` |

环境变量一律带 `DROVER_` 前缀（`DROVER_CORRAL_BIN`、`DROVER_NOTIFY_BIN`…），配置键不带。

**`BRANCH_GLOB` 两个坑**：写 `m*` 会把 `main` 自己匹配进来（代码里硬性排除了 `main`，但别依赖这个）；**非空却匹配到 0 个分支时门 2 判不过**，不是空过——「模式写错了」和「这件活没建分支」从 git 看一模一样，任何一种都不能当通过。

## 5. 两份文件的分工

交接目录里只有两份要紧的：

- **`queue.md` 只归你。** drover 只读它。`## 标题` 开一块，编号可省。正文里 `验收：<命令>` 按任务覆盖 `CHECK_CMD`，`做完：等我放行` 等价于 `drover hold`
- **`tasks.state` 只归 drover。** 每行一个 JSON 事件（`start` / `done` / `go` / `drop`），只追加。不要手改

看板**不存任何自己的状态**——刷新等于重跑。这是它一直好用的原因，别为了性能破例。

## 6. 排查

### 卡住了，不往下走

按顺序问：

```sh
drover list                  # 现在什么状态？「等你放行」还是「进行中」？
corral status <主控名字>      # 主控在干什么？idle 还是 working？
drover done <当前任务>        # 判据到底哪一条没过？它会逐条打出来
```

`drover done` 的输出会告诉你差在哪：

```
✗ 依据 收尾记号：6a1f2b3..main 里没有「收尾: 」开头的空提交
✓ 1 main 前进了：6a1f2b3 → 91ca678
— 2 里程碑分支都合进去了：没配 BRANCH_GLOB
```

`✗ 依据` 说明主控没打收尾记号。三种可能：活真没完；活完了但主控漏打（最常见）；项目 AGENTS.md 里压根没加那一行。

### 「等你」一直挂着

`门全开 + 没有记号` 同时对应三种情况：在等你拍板、搞砸了在原地转、刚结束一轮正在想。**drover 分不出来**，所以它只说「主控空闲着，判据还没满足——去看看」。`corral attach <主控名字>` 自己去看。

### 引擎不转

```sh
ps -eo pid,command | grep 'drover loop' | grep -v grep   # 引擎在跑吗
ls ~/.drover/<短名>/loop                                  # 这个项目开了吗
cat ~/.drover/<短名>/.loop.log                            # 最近几跳做了什么
cat ~/.drover/<短名>/.loop-wait                           # 停在哪一步、什么原因
```

> **别用 `pkill -f drover` 这类按名字批量杀进程。** 主控和别的 agent 的命令行里都带着项目名和工作目录，一条命令能把它们全杀掉。用起的时候记下的 PID。

### 门 2 永远过不了

`BRANCH_GLOB` 撞上一个**被遗弃、永远不会合并**的分支时，门 2 就再也过不了，之后每件活都卡死。这不是「没做完却判成做完了」，是反过来——**做完了永远判不成做完**。

查：`git branch --list '<你的 BRANCH_GLOB>'`，挨个 `git merge-base --is-ancestor <分支> main` 看哪个不过。

眼下的办法是删掉或合并那个废分支。（更好的修法——只算这次任务开始之后才出现的分支——记在 ROADMAP 里，还没实现。）

## 7. 什么时候该停掉它

止损点的完整清单在 [ROADMAP](ROADMAP.md)「止损点」一节。**自举阶段两周或 5 件任务**，出现以下任一条就停掉自动送任务、退回手动：

- 一次「没做完却判成做完了」，且事后查不出原因
- 为了 drover 的需求不得不改 corral 或 corral-dispatch（边界划错了，先修边界）
- 主控被送进来的任务打断正在做的事
- 你觉得盯着看板比自己手动喂任务还累

还有一条从前身那套东西里学来的，值得单独说：

> **队列一直往前走，会让你觉得它在正常工作；实际可能是判据在放水，而你已经不再检查了。这两种状态从内部看一模一样。**

唯一能穿透它的办法是**前五件活里做两次完整对照**：挑一件自己从头核一遍「它到底做完没有」，跟 drover 的判断比。成本是白干两遍，但它一次给出的信息比攒三个月的感受还多，而且是一次性动作，不依赖持续自律。

## 8. 三条不会变的

破一条，drover 的定位就垮了：

1. **只能往下依赖。** 不为 drover 的需求改 corral 或 corral-dispatch。真缺什么，先看能不能用现有命令组合出来
2. **不解析自然语言。** 完成判据只从 git 读。主控换个措辞就崩的东西，一律不要
3. **对目标仓库只读。** 循环跑起来之后对项目仓库只有 `git log` / `rev-parse` / `diff-tree` 这类读操作。（`drover init` 例外——那是你手动敲一次的安装动作。）

唯一贴着线走的是**收尾记号**：它确实要求主控多做一个动作。它不算反依赖，靠三条撑着——约定住在**项目自己的 AGENTS.md** 里（corral-dispatch 的 SKILL.md 一个字没动，主控不知道 drover 存在）、模板里明写「不写照样能跑」、漏打只会卡住不会误进。**少一条就得重新评估。**

反依赖的四个探针在 [AGENTS.md](../AGENTS.md)「反依赖的四个探针」一节，符合任何一条就是它正在发生。
