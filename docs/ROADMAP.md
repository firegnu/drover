## 从哪来

这个仓库从 herdsman（bounded-adversarial-review）clone 而来，历史全留。第一个提交 `4545f68` 砍掉了它的主题——写手 + 评审方的对抗式评审协议，以及为了管住那个昂贵过程长出来的全部外壳（findings、稳定编号、responses 格式、轮次上限、裁决文件、简报过期拦截）。

砍它的理由：证据门槛正是让评审变贵的那个东西，不是附带的。老 README 自己写着「评审通常比实现慢也更贵，因为证据要求让评审方在跑代码而非读代码」。审查这件事现在由 corral-dispatch 用更轻的方式承担（它的第 5、6 节），所以外壳没有存在理由。

**代价要认**：证据门槛没有了，误报会不会变多没有数据支撑——老仓库 143 个周期里 `precision.md` 只有 1 行填过、`escapes.md` 一条没有。「报告连续干净」和「它什么都没抓到」从内部看一模一样。这条教训直接适用于 drover 的记账：**记不出数就等于没记**。

## 定位

见 `README.md` 的三层表和 `AGENTS.md` 的硬规矩。一句话：corral 是基础设施，corral-dispatch 是内循环（主控在场），drover 是外循环（无人值守）。只能往下依赖。

内循环不是那份技能本身，是「主控会话 + 技能」。跑起来的是主控（例如 `owlet/main`）；drover 的操作对象是那个 agent，它甚至不需要知道主控读的是哪份技能。

## drover 管什么、不管什么

| 管 | 不管（内循环的事） |
|---|---|
| 队列：任务从哪来、什么顺序、插队、暂停、放弃 | 怎么拆 |
| 推进：做完自动送下一件；停住了叫醒 | 交给哪家 |
| 闸门：什么时候必须停下等人 | 几档 |
| 观察：看板 | 审不审、怎么审 |
| 记账：耗时、返工轮数、路由的实际表现 | 合不合得了 |

`bin/drover` 的队列语义（add / next / done / go / pause / hold / move / edit / drop，放行模式 vs 自动模式）整套落在左栏，**一条都不改语义**，只换传输层。

## 全部动作

1. 往主控送一句话（任务正文）
2. 只读核对 git

用到的 corral 命令只有三个：`send`、`status`、`ls`。

由此：

- **叫醒送的是任务正文本身**，和人手动粘一段任务进去一模一样。老仓库的 `loop_tick` 送的是固定那句 `LOOP_PROMPT`（让写手去跑 `review-task next`）——**那是内依赖外，必须改掉**，这是「只往下依赖」能不能立住的关键。
- 主控不在（`corral status` 查不到）：不重开，挂进看板「等你」，停止送任务。
- 主控上下文会涨，不用 drover 管：Claude Code 自己压缩；任务正文每次自带，任务文件和交接文件都在磁盘上。
- `corral send` 自带退出码 7（不是 idle）和 8（30 秒内有人在接入窗口里打字），老 `loop_tick` 手写的那些判断可以删。

## 完成判据：纯 git，零解析

> **2026-09-20 整节重写。** 原来写的是「三条都满足才算完成」，**那是错的**，而且和本节自己另一句「它证明不了：三条都满足时活真的干完了」直接矛盾。下面「三个死路」记的是推翻它的过程，别再走一遍。

### 门 vs 依据

「这件活完了吗」是个**语义判断**，而 AGENTS.md 三条硬规矩把 drover 做语义判断的路全堵死了：不解析自然语言、不接入 agent、不要求主控多做事。所以 drover 能看的只有 git 和 `corral ls`。

分清两件事，后面才说得清：

- **门**：现在是不是一个「可以去判断」的时刻。便宜、可观察，只决定**什么时候问**。
- **依据**：凭什么说这件活完了。**只有一个**。

门有这些（任一不满足就不问）：主控不是 `working`；这个仓库的 worktree 里没有活着的 agent（`corral ls` + `git worktree list` 映射）；工作区干净；`main` 前进了；`BRANCH_GLOB` 匹配到的里程碑分支都已经是 `main` 的祖先；静止持续够久。

**依据只有一条**：`base_sha..main` 区间里出现了一条**收尾标记提交**（见下）。

老仓库那条「**只读核对 git 和交接目录，不听 agent 一句话**」原则原样保留。**不解析「## 主控审查」那一节**，理由见 AGENTS.md 硬规矩第 3 条。

### 三个死路（都试过，都有反例，别再提）

找「完成」的外部代理信号，试了三个，每个都被真实工作流打穿：

| 提过的信号 | 反例 |
|---|---|
| **主控 idle 了** | 主控派完活就 idle，然后等子 agent 干几十分钟到几小时。**idle 在一件活里占绝大部分时间，而且正是它最忙的时候。** |
| **验收命令退出码 0** | 不是所有任务都写得出验收命令。硬性要求等于把写不出的活挡在外面。而且就算写了，`pytest -q` 只能证明没坏，证明不了「做了要求的三件事里的三件」。 |
| **派出去的 agent 从 `corral ls` 里消失** | 三种情况里只有一种成立：① 派出去→你说「关」→消失 ✓；② **主控自己干**，全程 0 个，无信号；③ **主控让已经开着的 agent 接着做下一件**，它们根本不消失，信号永远不来。 |

**这个模式本身就是结论**：工作流是故意灵活的，任何固定代理信号都有反例。再找第四个，大概率还有第四个反例。

### 出路：认出人的判断留下的痕迹

「这件活完了」本来就是**人做的判断**——corral-dispatch 第 7 节最后一步，主控把「还开着哪些 agent」报给用户，用户说关不关。**用户答话的那一刻就是判断发生的时刻。**

所以 drover 不该自己猜，该去**认出这个判断的痕迹**。办法：corral-dispatch 在收尾时往 `main` 上打一条空提交，首行带固定前缀：

```
收尾: M8-2 录结果前端、外来卷子
```

drover 的判别有**三道闸**，叠起来误判概率可以忽略：

1. **区间**：只在 `base_sha..main` 里找（发出这件活之后），之前的历史进不来
2. **空提交**：`git diff-tree --no-commit-id --name-only -r <sha>` 输出为空。正常提交总归改了东西，**既是空提交又带这个前缀的，不可能误撞**
3. **前缀**：首行 `^收尾:`

为什么是空提交而不是 `git tag`：轻量 tag 没有时间戳，「在某个 sha 之后」要绕着 `merge-base` 算；空提交自带时间和顺序，`git log <base>..main --grep` 一条命令就答了，而且跟着分支走，不会像 tag 那样漏推。

**为什么这不破坏独立性**（三条都要成立，破一条就是反依赖）：

- 标记里**不带 drover 的任务编号**。drover 的队列是串行的，同一时刻只有一件活在飞，所以「区间内出现过一条标记」就够，不需要知道是哪一件。要求主控回填 `T7` 才是为 drover 多做事。
- 技能里的措辞要用 **corral-dispatch 自己的理由**——「收尾时在 git 里留一条完成记录，方便之后翻 log 对照」。判别标准就是本文档「怎么算成功」里那条：**技能文件里搜不到「队列」「循环」「drover」这些词**。写成「给 drover 发信号」就破了。
- 它**自己就有用**：`git log --grep '^收尾:'` 一敲就是这个项目做完了哪些活，drover 在不在都成立。

**漏打标记时失败方向是安全的**，这条很重要：

```
主控漏打  →  drover 看不到完成 →  卡住、挂「等你」    ← 假阴性，你一眼看得出，按一下键就过去
绝不会    →  drover 以为完了   →  误发下一件          ← 假阳性
```

也就是说**这条约定不可能造成「没做完却判成做完了」**，只可能造成「做完了但还在等你点头」。正因为这样，全自动和人工推进两种模式可以共用同一套机制，区别只在标记没出现时谁来兜底。

> **待人点头**：这要改 `corral/corral-dispatch-skill/SKILL.md` 第 7 节，加一条收尾约定。AGENTS.md 明令「不许改 corral-dispatch」「给 corral 加任何东西先问人」，所以**措辞可以写，改由人来**。没点头就退回「门全开就停下问人」，drover 不自动完成任何任务。

**证据支持主控能遵守**：第 7 节已经是个编号清单，而且要求「按顺序核对，并在回复里说明结果」。owlet 上实测 **24 个里程碑分支落地，分支和 worktree 现在一个不剩**，清理纪律 24/24 执行到位。（ROADMAP 早先记的「jb-finetune 的 `m3/implementation` 合了没删」是**老内循环**留下的，不是 corral-dispatch，两回事。）

### 「它在等人」怎么识别

门全开、但没有收尾标记 → 它停在某处等人拍板（审查复核没过、和审查者有分歧、要推送、要花钱、发现设计对不上）。不需要内循环配合。

措辞上要克制：`idle + 没有标记` 同时对应三种情况——在等你拍板、搞砸了在原地转、刚结束一轮正在想。drover 分不出来，所以**页面上别写「它在等人拍板」这种确定的话**，写「主控空闲着，判据还没满足——去看看」。

### 门的两条细则（契约里挖出来的）

**「idle 了」不等于「停下了」。** corral 契约「取值」一节写明：`idle` **只表示这一轮结束，不代表 agent 不会再动**——它可能自己开新一轮（例如后台命令跑完后自注入一条输入），契约还专门提示看 `last_input_source`（取值 `send` / `human` / `agent`）。所以门上要加两道：看 `last_input_source`，是 `agent` 就不算停下；以及留一次观察间隔，别在 `idle` 刚出现那一刻就判。

**`state` 是 `unknown` 时不猜。** 主控不是 Claude Code 或 Codex 时没有钩子，状态无从得知。那就不判断，挂进看板「等你」让人自己去看。

### 判据第 2 条（里程碑分支）的历史

它现在是**门**的一条，不是依据。下面几段记的是它踩过的坑。

**这一条最初写的是「没有残留的里程碑分支」，2026-09-20 改掉了。** 真实仓库给的反馈：jb-finetune 的 `m3/implementation` 已经合进 main 但分支没删。也就是说「分支不存在」不是普适的 git 常识，它依赖 corral-dispatch 第 7 节那套收尾纪律（`git worktree remove` + `git branch -d`），换个项目就不成立，会一直判成「没做完」（假阴性）。改成问「活合进去了吗」，删不删分支都成立，语义也更准。

**第 2 条会空真（第 2 步已挡）。** 匹配不到分支时，「所有里程碑分支都已经是 `main` 的祖先」**空真**——对空集合跑 `--is-ancestor`，一次都不跑，第 2 条直接过。而「匹配到 0 个」有三种来源，从 git 这边看一模一样：模式在配置里写错了、corral-dispatch 换了分支命名、这件活压根没建分支。任何一种都会让判据在活没干完时放行，正是止损点里写的那条「没做完却判成做完了」。**处理方式：`BRANCH_GLOB` 非空却匹配到 0 个 → 判不过；`BRANCH_GLOB` 留空 → 这条标「不适用」，不算过也不算不过。**

**原先写的 `'<前缀>-*'` 是错的，2026-09-20 改成 `BRANCH_GLOB`。** 拿两个真实项目一比就露馅：owlet 的里程碑分支是 `m8-2-backend`，jb-finetune（靶场）的是 `m3/implementation`。前缀填 `m` 得到模式 `m-*`，**两边都匹配 0 个**——也就是说照原公式写，判据在两个真实项目上都会踩空真。放宽成 `m*` 又会把 `main` 自己卷进来。两边都能用的是 `m[0-9]*`。所以配置里存的是**直接交给 `git branch --list` 的模式**，代码不再自作主张拼 `-*`，另外在代码里硬性排除 `main` 自己。

**M7 那个反例已经验过了（2026-09-20，第 2 层回放）**：owlet 的 `m7-backend` 确实落地了两次（`c69e874` 和 `e320f05`），中间主控又发起了一轮改动。回放结果是**判据第 2 条挡住了它**——第一次落地时 `m7-frontend` 还开着，不是所有分支都合入。

但别把这当成设计的功劳，**那是时机赶巧**：如果那一刻恰好没有兄弟分支开着，第 2 条就会放行。这正是为什么「合进 main」只能当门、不能当依据——一件活可以合很多次，`main` 那边看不出哪一次是最后一次。owlet 上一个里程碑最多落地 **6 次**（M8：m8-backend / m8-frontend / m8-2-backend / m8-2-frontend / m8-3-backend / m8-3-frontend）。

**同一次回放还挖出一个会让 drover 完全停摆的坑**：`BRANCH_GLOB` 匹配到一个**被遗弃的、永远不会合并的**分支，第 2 条就永远过不了，之后每一件活都卡死。靶场上现成两个：`m4/parallel-scalable-generation`（2026-09-14 最后提交）和 `m4/planning`（2026-09-02），配上 `m[0-9]*` 就会踩。这不是「没做完却判成做完了」，是反过来——**做完了永远判不成做完**。第 1 层的合成测试测不出来，它造的分支都是这次任务新建的。
修法（还没做）：只看**这次任务开始之后才出现**的分支——分支的第一个提交不在 `base_sha` 的历史里，才算这次的。和判据第 1 条同一个基准，不引入新配置项。

>
> **测试怎么办**：把「算出要显示什么」和「画出来」分开——`view_model(projects) → dict`，断言全打在这个纯数据上，比 grep HTML 更结实（不会因为换个类名就挂）；`draw()` 那层薄到补一条「渲染进假屏幕不崩、不越界」的冒烟就够。现有 15 块断言大部分能平移。
>

**它证明什么**：三条都满足时返回 true。**它证明不了**：三条都满足时活真的干完了。

### 第 2 层：判据符不符合现实（一次性，离线回放）

假阳性和假阴性只有真实流程里才会露出来。做法：拿一个真跑过内循环的项目，**把它的 git 历史和任务文件当只读数据**，在每个里程碑的各个时间点上算一遍三条判据，和实际完成时刻对照。

- 全机器上唯一有真实痕迹的是 **owlet 的 M0–M8**（一个里程碑一个分支一个 worktree、任务文件在 `docs/任务/`、合并进 main）。jb-finetune 的历史用不了——它跑的是老内循环，没有里程碑分支和任务文件，判据里三条有两条无从谈起。
- 这**不需要在 owlet 上跑 drover**，只读它的历史，不碰它的 agent、不改它任何文件。
- 重点查：**假阳性**（某个时刻三条碰巧都满足但活没完，比如前端先合了后端还在做）、**假阴性**（活完了但判据不满足，比如分支没删）、以及上面记的 M7 反例。
- 结论写回本文档。**如果 owlet 的历史里就有判据挡不住的反例，先改设计再往下走**——改文档比改代码便宜。

> **待人点头**：只读 owlet 的 git 历史和任务文件。没点头就跳过这一层，代价是判据的正确性推迟到第 3 层才暴露，那时候改的是代码。

- **一律放行模式**（每件做完等人 `go`），风险可控：drover 坏了最多是卡住自己，不会把别人的开发带沟里。

2026-09-20 从 jb-finetune 本地 clone（`--no-hardlinks`），**三个远端全部删除**（公司内网 GitLab、外部 SSH、GitHub），不许 push。真的 jb-finetune 只读、不碰，它还跑在老 herdsman / herdr 上。

### 第 4 层：jb-finetune 迁移（最后做）

jb-finetune 今天跑的是**老内循环**（写手 + 评审方 + `request-review`），不是主控 + corral-dispatch。所以这是**两次迁移**，必须拆开，一起上会分不清问题出在哪一层：

1. **换内循环**：写手 + 评审方 → 主控 + corral-dispatch。改变的是开发方式本身（任务文件、里程碑分支、worktree），和 drover 无关。手动跑两三个里程碑。
2. **接外循环**：稳定产生那些痕迹之后，drover 才接得上。先放行模式，稳了再试自动模式。

老 herdsman 仓库在第 1 步完成前保持能用，之后再决定归档还是删。

## 怎么算成功

- 一台没有 herdr、没有 tmux 的机器上，drover 能把队列里的任务一件接一件送进主控，人不在场时队列继续推进。
  **「人不在场继续推进」成立的前提是收尾标记那条约定落地**（见完成判据那一节）。没落地的话这条降级成：drover 无人值守地排队、送达、盯着，**完成由人按一下键确认**——队列不会自己往下走。这不是折中，是诚实：判不出完成就别假装能自动推。
- 自举阶段连续 **5 件任务**、迁移后连续 **10 件任务**：零次「送了没到」；零次「没做完却判成做完了」；主控停下等人时，看板和通知能在 5 分钟内让人知道。
- **拆掉 drover，目标项目照常工作**（真跑一遍验证依赖方向）。收尾标记落地之后这条照样成立：那条空提交在 `git log` 里人自己也读得懂，drover 在不在都有用。
- corral 一行没改；corral-dispatch 的技能文件里搜不到队列、循环、drover 这类词。**这条是收尾标记那段措辞的验收标准**——写成「给 drover 发信号」就破了，写成「收尾时留一条完成记录」就不破。
- 重装 drover、升级 corral，正在跑的 agent 都不受影响。
