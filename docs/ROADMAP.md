## 从哪来

这个仓库从 herdsman（bounded-adversarial-review）clone 而来，历史全留。第一个提交 `4545f68` 砍掉了它的主题——写手 + 评审方的对抗式评审协议，以及为了管住那个昂贵过程长出来的全部外壳（findings、稳定编号、responses 格式、轮次上限、裁决文件、简报过期拦截）。

砍它的理由：证据门槛正是让评审变贵的那个东西，不是附带的。老 README 自己写着「评审通常比实现慢也更贵，因为证据要求让评审方在跑代码而非读代码」。审查这件事现在由 corral-dispatch 用更轻的方式承担（它的第 5、6 节），所以外壳没有存在理由。

**代价要认**：证据门槛没有了，误报会不会变多没有数据支撑——老仓库 143 个周期里 `precision.md` 只有 1 行填过、`escapes.md` 一条没有。「报告连续干净」和「它什么都没抓到」从内部看一模一样。这条教训直接适用于 drover 的记账：**记不出数就等于没记**。

## 定位

见 `README.md` 的三层表和 `AGENTS.md` 的硬规矩。一句话：corral 是基础设施，corral-dispatch 是内循环（主控在场），drover 是外循环（无人值守）。只能往下依赖。

内循环不是那份技能本身，是「主控会话 + 技能」。跑起来的是主控（例如 `owlet/main`）；drover 的操作对象是那个 agent，它甚至不需要知道主控读的是哪份技能。

## drover 管什么、不管什么

| 管 | 不管（内循环的事） |
|---|---|
| 队列：任务从哪来、什么顺序、插队、暂停、放弃 | 怎么拆 |
| 推进：做完自动送下一件；停住了叫醒 | 交给哪家 |
| 闸门：什么时候必须停下等人 | 几档 |
| 观察：看板 | 审不审、怎么审 |
| 记账：耗时、返工轮数、路由的实际表现 | 合不合得了 |

`bin/drover` 的队列语义（add / next / done / go / pause / hold / move / edit / drop，放行模式 vs 自动模式）整套落在左栏，**一条都不改语义**，只换传输层。

## 全部动作

1. 往主控送一句话（任务正文）
2. 只读核对 git

用到的 corral 命令只有三个：`send`、`status`、`ls`。

由此：

- **叫醒送的是任务正文本身**，和人手动粘一段任务进去一模一样。老仓库的 `loop_tick` 送的是固定那句 `LOOP_PROMPT`（让写手去跑 `review-task next`）——**那是内依赖外，必须改掉**，这是「只往下依赖」能不能立住的关键。
- 主控不在（`corral status` 查不到）：不重开，挂进看板「等你」，停止送任务。
- 主控上下文会涨，不用 drover 管：Claude Code 自己压缩；任务正文每次自带，任务文件和交接文件都在磁盘上。
- `corral send` 自带退出码 7（不是 idle）和 8（30 秒内有人在接入窗口里打字），老 `loop_tick` 手写的那些判断可以删。

## 完成判据：纯 git，零解析

> **2026-09-20 整节重写。** 原来写的是「三条都满足才算完成」，**那是错的**，而且和本节自己另一句「它证明不了：三条都满足时活真的干完了」直接矛盾。下面「三个死路」记的是推翻它的过程，别再走一遍。

### 门 vs 依据

「这件活完了吗」是个**语义判断**，而 AGENTS.md 三条硬规矩把 drover 做语义判断的路全堵死了：不解析自然语言、不接入 agent、不要求主控多做事。所以 drover 能看的只有 git 和 `corral ls`。

分清两件事，后面才说得清：

- **门**：现在是不是一个「可以去判断」的时刻。便宜、可观察，只决定**什么时候问**。
- **依据**：凭什么说这件活完了。**只有一个**。

门有这些（任一不满足就不问）：主控不是 `working`；这个仓库的 worktree 里没有活着的 agent（`corral ls` + `git worktree list` 映射）；工作区干净；`main` 前进了；这次任务建的分支（`base_sha` 之后出现的）都已经是 `main` 的祖先；静止持续够久。

**依据只有一条**：`base_sha..main` 区间里出现了一条**收尾记号**（空提交，见下）。

老仓库那条「**只读核对 git 和交接目录，不听 agent 一句话**」原则原样保留。**不解析「## 主控审查」那一节**，理由见 AGENTS.md 硬规矩第 3 条。

### 三个死路（都试过，都有反例，别再提）

找「完成」的外部代理信号，试了三个，每个都被真实工作流打穿：

| 提过的信号 | 反例 |
|---|---|
| **主控 idle 了** | 主控派完活就 idle，然后等子 agent 干几十分钟到几小时。**idle 在一件活里占绝大部分时间，而且正是它最忙的时候。** |
| **验收命令退出码 0** | 不是所有任务都写得出验收命令。硬性要求等于把写不出的活挡在外面。而且就算写了，`pytest -q` 只能证明没坏，证明不了「做了要求的三件事里的三件」。 |
| **派出去的 agent 从 `corral ls` 里消失** | 三种情况里只有一种成立：① 派出去→你说「关」→消失 ✓；② **主控自己干**，全程 0 个，无信号；③ **主控让已经开着的 agent 接着做下一件**，它们根本不消失，信号永远不来。 |

**这个模式本身就是结论**：工作流是故意灵活的，任何固定代理信号都有反例。再找第四个，大概率还有第四个反例。

### 出路：认出收尾在 git 里留下的记号

「这件活完了」本来就是**内循环的判断**——合并、审查、清掉 worktree 和分支，这一串走完才叫收尾。drover 猜不出来，但可以**认出它留下的记号**：项目在自己的 `AGENTS.md` 里要求主控收尾时往 `main` 上补一条空提交，首行固定前缀加一句话。

```
收尾: M8-2 录结果前端、外来卷子
```

#### 住在哪：项目的 AGENTS.md，不是技能

**2026-09-20 落地。** corral 侧提交 `649ca22`，只改 `corral-dispatch-skill/项目AGENTS模板.md` 两处，**SKILL.md 一个字没动**。最终原文（以仓库为准，drover 的检测器按它对齐）：

模板第 1 节代码块，「合并」那行后面：

> - 收尾记号：一件活合并完、worktree 和分支清干净之后，在 main 上补一条空提交（`git commit --allow-empty`），首行写「\<前缀\>: 」加一句话说明这件活是什么。只记真正落地的活；说好不合并、停在审查的不记。

模板第 2 节表格：

> \| 收尾记号 \| 一件活落地了在 git 里留个固定记号，`git log --grep` 一敲就是做完的清单 \| 不写照样能跑；进度只能靠翻合并提交和交接文件看，没有机器认得的记号 \|

**原先提的是改 SKILL.md 第 7 节，被 corral 主控否了。三条理由记下来，别再提一遍：**

1. **内循环没有净收益。** 「做完了哪些活、各在什么时候」内循环已经有三处答案：`git log --merges`、`docs/任务/` 下的任务文件、以及第 7 节自己就要求更新的**交接文件**。空提交多出来的只有「机器可读」，而需要机器可读的是外循环。
2. **行为泄漏。** 技能里搜不到「队列」「循环」「drover」只说明**词汇**没泄漏；这个约定存在的唯一理由还是 drover。
3. **强加提交约定。** 一份通用技能去规定每个项目的 commit message 格式（还是中文前缀），比引入一个概念更侵入。

改投模板之后，三条各自的下场：第 3 条被**尖括号占位符**解掉（前缀由项目自己填）；第 1 条力道大减（模板本来就是「这个项目要不要」的参数清单，每行都配一句「不写会怎样」）；**第 2 条原封不动地留着**——这是明知故犯，见 AGENTS.md 硬规矩第 3 条的例外段。

为什么模板能承载而技能不能：模板是给人复制进项目 AGENTS.md 的**参数清单**，和「本地合并还是开 PR」「推不推送」「这个项目不用路由」同级，而且已经有现成的兄弟行（`- 合并：审查通过后<…>`）；技能是**行为指令**，对所有项目无条件生效。

#### drover 的四道闸

1. **区间**：只在 `base_sha..main` 里找（发出这件活之后），之前的历史进不来
2. **父提交恰好一个**：`git rev-list --parents -n1 <sha>` 输出恰好两个词（自己 + 一个父）
3. **空提交**：`git diff-tree --no-commit-id --name-only -r <sha>` 输出为空
4. **前缀**：首行 `^<前缀>[:：]`，前缀读 `.drover.conf` 的 `DONE_MARK`，全角半角冒号都收

**第 2 道不是锦上添花，2026-09-20 在合成仓库里验过：合并提交在 `git diff-tree` 眼里输出也是 0 行**——不给 `-m` / `-c` 时 git 对合并提交默认不出 diff。所以主控哪天在合并摘要里恰好写了前缀开头，光靠「空 + 前缀」会误判。加一句父提交数就堵死。

为什么是空提交而不是 `git tag`：轻量 tag 没有时间戳，「在某个 sha 之后」要绕着 `merge-base` 算；空提交自带时间和顺序，`git log <base>..main --grep` 一条命令就答了，而且跟着分支走，不会像 tag 那样漏推。

**空提交的代价，记在这里**：`git rebase` 默认会丢掉空提交（除非 `--keep-empty`）。项目换成 rebase 流或 squash merge，记号会静悄悄消失，drover 表现成「认不出完成、卡住等你」——失败方向仍然安全，但你会误以为是主控漏打。现在用它的两个项目（owlet、drover 自己）都是本地 `--no-ff` 合并进 `main`，不踩；**换合并方式之前先想到这一条**。tag 在这一点上反而稳，但它的时间戳问题更麻烦，所以还是空提交。

#### 粒度：一次收尾一条记号

多件活一起合并、只清一次，就只有一条记号。**不收紧**（corral 主控定的）：记号记的是**一次收尾事件**，不是一个工作单元；逼内循环去发明「一件活」的硬定义，正是外循环把自己的需求塞回去。drover 这边正好对得上——队列是串行的，同一时刻只有一件活在飞，「区间内出现过一条记号」就够，不需要知道是哪一件。**要求主控回填 `T7` 那种才是为 drover 多做事。**

#### 为什么这仍然不算反依赖

三条都要成立，破一条就得重新评估：

- 约定住在**项目自己的 `AGENTS.md`** 里。corral-dispatch 的 SKILL.md 一个字没动，主控不知道 drover 存在。
- 模板里明写**「不写照样能跑」**。不填这条的项目，内循环照常工作。
- 它**自己就有用**：`git log --grep` 一敲就是这个项目做完了哪些活，drover 在不在都成立。

corral 主控另给了**四个反依赖探针**，抄在 AGENTS.md「反依赖的四个探针」一节。最隐蔽的是第 4 条：**这条约定不进 corral 的任何测试**——一旦 corral 断言了它，删掉模板那行会让 corral 挂掉，那才是真反依赖。

**漏打记号时失败方向是安全的**，这条很重要：

```
主控漏打  →  drover 看不到完成 →  卡住、挂「等你」    ← 假阴性，你一眼看得出，按一下键就过去
绝不会    →  drover 以为完了   →  误发下一件          ← 假阳性
```

也就是说**这条约定不可能造成「没做完却判成做完了」**，只可能造成「做完了但还在等你点头」。正因为这样，全自动和人工推进两种模式可以共用同一套机制，区别只在记号没出现时谁来兜底。

#### 为什么不走「drover 不判断，改成问」

corral 主控提过第三条路：drover 别判断完成，把下一件直接送给主控，让它自己决定要不要开工（上一件没收尾就回一句、不开工）。判断留在本来就该做判断的那一层，零新增约定。

**不走，因为它给 drover 零信号**，砍掉 drover 两件事里的一件：看板的「做完的」那栏永远是空的，记账整块作废。而且 drover 要知道主控是接了还是回绝了，只能解析它的自然语言回复——AGENTS.md 硬规矩第 3 条明令禁止；不解析就只能盲目重送，任务会被静悄悄丢掉，队列状态跑进主控的上下文里，等于内循环吃掉外循环。

**但它白送了一层网**：SKILL.md 第 1 节 2026-09-20（`88c8174`）刚加了「派新活之前，先确认上一件已经收尾，没收尾不派新活」。这是 corral-dispatch 为自己加的，所以就算 drover 哪天误判提前发了下一件，**主控自己会挡一道**。

#### 证据和已知风险

**主控能遵守：** 第 7 节已经是个编号清单，而且要求「按顺序核对，并在回复里说明结果」。owlet 上实测 **24 个任务分支落地，分支和 worktree 现在一个不剩**，清理纪律 24/24 执行到位。（ROADMAP 早先记的「jb-finetune 的 `m3/implementation` 合了没删」是**老内循环**留下的，不是 corral-dispatch，两回事。）

**最后一个动作最容易漏。** corral 主控指出：2026-09-20 上午刚修过一个真问题——owlet 的 M8 连续两轮合并完都没清 worktree，主控自己的诊断是「流程是合并 → 更新交接 → 下一件，**收尾没有固定的触发点**」。`88c8174` 修的就是这个，第 7 节现在有固定触发点了，记号正好挂在那个点上。但把新动作放在最容易被跳过的那一步末尾，漏打概率天然高。**这条没解掉，靠的是上面那个失败方向**：漏打只会卡住，按一下键就过去。

**这条线是明知故犯。** herdsman 的 ROADMAP 写过「三个会破坏它的诱惑」，第 2 条原文就是「**让主控写个 done 标记文件——内依赖外，主控在做一件只对外循环有意义的事**」（`bc9fda3` 写下，`f3036aa` 建 drover 时随 ROADMAP 精简掉了，不是有意废除）。空提交就是那个 done 标记，换了个载体。代价摆在桌上之后决定越线，理由是：不越线判不出完成，外层循环整个不成立。

### 「它在等人」怎么识别

门全开、但没有收尾记号 → 它停在某处等人拍板（审查复核没过、和审查者有分歧、要推送、要花钱、发现设计对不上）。不需要内循环配合。

措辞上要克制：`idle + 没有标记` 同时对应三种情况——在等你拍板、搞砸了在原地转、刚结束一轮正在想。drover 分不出来，所以**页面上别写「它在等人拍板」这种确定的话**，写「主控空闲着，判据还没满足——去看看」。

### 门的两条细则（契约里挖出来的）

**「idle 了」不等于「停下了」。** corral 契约「取值」一节写明：`idle` **只表示这一轮结束，不代表 agent 不会再动**——它可能自己开新一轮（例如后台命令跑完后自注入一条输入），契约还专门提示看 `last_input_source`（取值 `send` / `human` / `agent`）。所以门上要加两道：看 `last_input_source`，是 `agent` 就不算停下；以及留一次观察间隔，别在 `idle` 刚出现那一刻就判。

**`state` 是 `unknown` 时不猜。** 主控不是 Claude Code 或 Codex 时没有钩子，状态无从得知。那就不判断，挂进看板「等你」让人自己去看。

### 判据第 2 条（本次任务建的分支）

它是**门**的一条，不是依据。

**2026-09-21 定：不存在「里程碑分支」这类东西，`BRANCH_GLOB` 删掉。** 「里程碑」从头到尾只是**人对「某次功能完成」的叫法**（用户原话：「本来就没有所谓的里程碑，只是我这么叫而已，最多我会自己打一个 tag 上去」），和平常一个功能做完没有区别，不是 drover 该建模的实体。第 2 条要认的是**这次任务建的分支**，而认它的正确依据是 `base_sha`——`m6-branch-filter` 已经在这么做了，分支名模式只是套在外面的一层壳。

壳去掉之后这条是：**枚举所有本地分支**（`main` 自己永远排除），用 `git merge-base --is-ancestor <base_sha> <branch>` 过滤出包含本次起点的，问它们是不是都已经是 `main` 的祖先。

- **`BRANCH_GLOB` 连同空真防护一起消失。** 空真防护当初防的是「模式写错了」和「分支命名变了」，没有模式就没有这两种错。剩下那个来源——**过滤完一个分支都不剩**——现在是**正常情况**：守纪律的项目一件活干完分支就删了，本来就该空真通过。**这正是那个死锁的解法**，守纪律的项目不必再把整条标「不适用」。唯一还落在危险那侧的来源（本次分支从 `base_sha` 之前的点建出、被当遗留分支排除）见下面「已知限制」，2026-09-21 人已裁定接受。
- **代价**：人自己开的、`base_sha` 之后建出来的实验分支会被卷进来，让第 2 条判不过。方向是**假阴性**（卡住，看得见），不是误推进——和止损点里写死不许发生的那条相反，可以接受。

**drover 不读 tag。** 人可能在某次功能完成后自己打个 tag，那是人的事，drover 不看、也不该看：硬规矩第 3 条（不要求人或主控为 drover 多做任何事），收尾记号已经是唯一一次破例，不能再开第二个。

#### 它踩过的坑（历史，措辞里的「里程碑」是当时的叫法）

**这一条最初写的是「没有残留的里程碑分支」，2026-09-20 改掉了。** 真实仓库给的反馈：jb-finetune 的 `m3/implementation` 已经合进 main 但分支没删。也就是说「分支不存在」不是普适的 git 常识，它依赖 corral-dispatch 第 7 节那套收尾纪律（`git worktree remove` + `git branch -d`），换个项目就不成立，会一直判成「没做完」（假阴性）。改成问「活合进去了吗」，删不删分支都成立，语义也更准。

**空真那一关（2026-09-20 加防护，2026-09-21 随 `BRANCH_GLOB` 一起作废）。** 模式匹配不到分支时，「所有分支都已经是 `main` 的祖先」**空真**——对空集合跑 `--is-ancestor` 一次都不跑，第 2 条直接过。而「匹配到 0 个」有三种来源，从 git 这边看一模一样：模式写错了、分支命名变了、这件活压根没建分支。当时的处理是「非空却匹配到 0 个 → 判不过」。**这个防护本身又和「合并后删分支」的收尾纪律正面撞车**：守纪律的项目一件活干完分支就没了，必然匹配 0 个，第 2 条永远判不过——2026-09-21 在本仓库实测就是这个结果，只能把 `BRANCH_GLOB` 留空、整条标「不适用」。去掉那层壳之后两个问题同时消失。

**`'<前缀>-*'` 那个公式是错的，2026-09-20 改成 `BRANCH_GLOB`（2026-09-21 整个删掉）。** 拿两个真实项目一比就露馅：owlet 的分支是 `m8-2-backend`，jb-finetune（靶场）的是 `m3/implementation`。前缀填 `m` 得到 `m-*`，**两边都匹配 0 个**；放宽成 `m*` 又把 `main` 自己卷进来；两边都能用的只有 `m[0-9]*`。**要靠人填对一个 glob 才不判错，这件事本身就是设计有问题**——现在依据换成 `base_sha`，不需要人填任何东西。

**M7 那个反例已经验过了（2026-09-20，第 2 层回放）**：owlet 的 `m7-backend` 确实落地了两次（`c69e874` 和 `e320f05`），中间主控又发起了一轮改动。回放结果是**判据第 2 条挡住了它**——第一次落地时 `m7-frontend` 还开着，不是所有分支都合入。**这条价值和「里程碑」无关，去掉概念之后照样成立**：一件活可以拆成几个分支并行做（corral-dispatch 本来就会），兄弟分支还开着就说明没干完。

但别把这当成设计的功劳，**那是时机赶巧**：如果那一刻恰好没有兄弟分支开着，第 2 条就会放行。这正是为什么「合进 main」只能当门、不能当依据——一件活可以合很多次，`main` 那边看不出哪一次是最后一次。owlet 上一件活最多落地 **6 次**（人叫它 M8：m8-backend / m8-frontend / m8-2-backend / m8-2-frontend / m8-3-backend / m8-3-frontend）。

**同一次回放还挖出一个会让 drover 完全停摆的坑**：模式匹配到一个**被遗弃的、永远不会合并的**分支，第 2 条就永远过不了，之后每一件活都卡死。靶场上现成两个：`m4/parallel-scalable-generation`（2026-09-14 最后提交）和 `m4/planning`（2026-09-02），配上 `m[0-9]*` 就会踩。这不是「没做完却判成做完了」，是反过来——**做完了永远判不成做完**。第 1 层的合成测试测不出来，它造的分支都是这次任务新建的。
**2026-09-21 修掉了**（`m6-branch-filter`）：只看**这次任务开始之后才出现**的分支——`git merge-base --is-ancestor <base_sha> <branch>` 成功（分支包含 `base_sha`），才算这次的。和判据第 1 条同一个基准，不引入新配置项。`base_sha` 为空时整条标「不适用」：退回旧行为等于留着死锁，判成不过又会在正常配置下凭空卡住。**这一步实际上已经把依据从分支名换成了 `base_sha`**，同日晚删掉 `BRANCH_GLOB` 只是把外面那层壳一并去掉。

> 原先这一句写的是「分支的第一个提交不在 `base_sha` 的历史里，才算这次的」。**那句区分不开两者**——遗留分支和本次新建分支的首个提交都不在 `base_sha` 的历史里，照它实现等于没改。2026-09-21 改成上面的判别式。

**顺带挖出一条假阳性**（交叉审查发现，同一次落地修掉）：`git merge-base --is-ancestor` 的退出码 1（确定不包含）和 128（查询失败，比如对象损坏）原先被 `returncode == 0` 混成一类，查询失败的分支会被当成「遗留分支」静默排除。只要同时还有一个包含 `base_sha` 且已合入的分支，第 2 条就会**误过**——正是止损点里写死不许发生的那条。现在只有 1 算确定不包含，其它退出码令第 2 条判不过并报出分支名和 git 的 stderr。教训可以推广：**把错误当成正常结果吞掉**，比逻辑写反更难看出来，而且失败方向往往落在危险那侧。

### 判据第 3 条的结果怎么上看板（2026-09-21 夜定）

第 3 条要跑人配的验收命令（drover 自己是整套测试，实测 22 秒）。看板 30 秒刷一次、每个项目都渲染，渲染时跑等于每半分钟把所有项目的测试全跑一遍——所以渲染一律 `do_check=False`，第 3 条标「—」。**结果因此永远到不了屏幕上**，人只能切出去敲 `drover done`。

**定下来的做法**：跑了第 3 条的那一次，把结果写进交接目录的 `.check-result`，看板只读。

- **谁写**：`bin/drover`（`drover go` 核对进行中任务，以及 `drover done` 的路径，人手动敲的和循环引擎调的都算）。**不是看板写**——看板不存自己的状态，刷新等于重跑，这条不破例。和 `.loop-wait`、`.criteria-checked` 同一个路子：归 `bin/drover` 所有，原子写（tmp + `os.replace`）。
- **写什么**：`{"task": 任务 id, "main": 跑的时候 main 的 sha, "cmd": 验收命令原文, "ok": true/false/null, "why": 理由, "t": 时间戳}`。
- **陈旧怎么判**：看板拿当前的 `task` / `main` sha / `cmd` 和文件里的比，**三样全都一致才显示结果**，否则照旧显示「—」并说明是哪一样对不上。三样任一变了，上次的结果就不代表当前状态了。
- **显示**：`✓ 3 验收命令过了（3 分钟前跑的）`。时间必须带上——见下面的限制。

**已知限制（接受）**：工作区的改动 sha 捕捉不到。`main` 没变但文件改了，上次结果照样显示。**所以显示时一定要带「多久之前跑的」**，让人自己判断。理由：drover 对目标仓库只读，工作区归人和主控管；而且这只是**显示**，真正要判的时候（`drover done`、引擎自动核对）照旧现跑，不读这个文件。**这个文件只喂看板，绝不参与任何判断**——和 `m7-accounting` 里「路由：」行那条同样的边界。

### 记 done 折进 `drover go`（2026-09-21 定，2026-09-22 实现）

一件活原来要人敲两次：`drover done` 核对加记账、`drover go` 放行。**用户定：只留 `g`。**

改法：`cmd_go` 时任务若还在「进行中」，先跑一次 `check_done`——过了就写 `done` + `go` 两条事件；没过就把原因原样打出来、拒绝放行（输出和现在的 `drover done` 一样）。已经 `done` 过的（循环自动记的）照旧只写 `go`。

**要保住的**：判据、依据、工作区检查一条不少，只是挪进 `g`；`tasks.state` 仍然是 `start → done → go`，看板记账不变；档 2（`loop on + GATE=1`）和档 3 照常工作。

**实现取舍**：保留 `drover done`，供兼容脚本、单独核对并记完成和引擎现有路径使用；日常直接按 `g` / `drover go`。两者共用一次核对、报告和记完成，`CHECK_CMD` 每次核对只跑一次，报告复用结果，显示缓存仍不参与判断。手动缺收尾记号但门和工作区检查全过时，保留明确警告并允许人确认；自动循环仍必须先看到记号。

**派发边界**：`go` 不调用 `next`，成功返回 0；手动下一件仍按 `n`。循环开着时，直接核对完成的路径补上现有 `.loop-wait` 标记，让引擎下一跳推进，暂停仍挡住派发。`done` 原有的退出码 8、放行等待和自动模式派发行为不带进 `go`。

> **为什么不是「翻到档 2 就行了」**：档 2 只是把 `drover done` 从人手上挪给引擎，那一步还在，而且要养一个常驻进程。用户要的是**这一步整个不存在**，不管什么档位。主控在这里来回误解了四轮，记下来别再走一遍。
>
> **为什么不是「见到收尾记号就直接记 done、什么都不查」**：那等于完全信任主控打的空提交。判据第 2 条（分支都合进去了）抓过三次真 bug（`m6`、`m9`、`m12`），目前还不该给这个信任。判据第 1 条（`main` 前进了）确实是冗余的——收尾记号是在 `base_sha..main` 区间里找的，找得到就说明 `main` 必然前进了——但删不删另说。

### 这条判据的已知限制（2026-09-21 人裁定接受）

`--is-ancestor` 证明的是「分支**包含** `base_sha`」，不是「分支是这次**新建**的」。git 不存分支创建时间，这个 gap 补不上，于是：

- **本次任务的分支若从 `base_sha` 之前的点建出，会被当成遗留分支排除。** 排除之后剩下的分支要么为空、要么都已合入，第 2 条就判过——**方向是危险那侧**。（`BRANCH_GLOB` 删掉之前，这条要「同时还有一个包含 `base_sha` 且已合入的分支」才触发，因为空集合另有防护挡着；防护随 glob 一起去掉之后，**这条更容易触发了**，这是那次改动明知的代价。）
- 派发前就存在、且恰好指向 `base_sha` 的分支，会被算成这次的（旧实现也如此，属既有边界）。

**接受它，不改判别式**，理由三条：corral-dispatch 的纪律是从 `main` 建 worktree 分支，从更早的点建属于违规；三条判据是**门**不是**依据**，收尾记号还兜着一层；触发要几个条件同时成立。

**真要彻底修**，路子是派发时把当时已有的分支名和 tip 存进队列条目，之后只认「新出现的、或 tip 变了的」。那是 drover 自己的状态，不要求主控或 corral 多做任何事——但它是设计变更，**动之前先问人**。

## D2 验证计划

四层，从便宜到贵，**不要跳级**：

### 第 1 层：实现对不对（仓库自带，随 D1 一起做）

用**假的 `corral` 命令** + **合成 git 仓库**，不依赖真的 corral、不依赖真的 agent、不花钱。沿用老仓库模拟 herdr 的做法。

- 送任务：主控不是 idle（退出码 7）、30 秒内有人在打字（退出码 8）、主控不存在、送达确认超时
- 队列语义：`tests/drover.sh` 里那一整套（add / next / done / go / pause / hold / move / edit / drop、放行 vs 自动、`--expect` 冲突）改完传输层后仍要全过

### 第 2 层：判据符不符合现实（一次性，离线回放）

假阳性和假阴性只有真实流程里才会露出来。做法：拿一个真跑过内循环的项目，**把它的 git 历史和任务文件当只读数据**，在每件活的各个时间点上算一遍三条判据，和实际完成时刻对照。

- 全机器上唯一有真实痕迹的是 **owlet 的 M0–M8**（人给每件活起的名字；一件活一个分支一个 worktree、任务文件在 `docs/任务/`、合并进 main）。jb-finetune 的历史用不了——它跑的是老内循环，没有任务分支和任务文件，判据里三条有两条无从谈起。
- 这**不需要在 owlet 上跑 drover**，只读它的历史，不碰它的 agent、不改它任何文件。
- 重点查：**假阳性**（某个时刻三条碰巧都满足但活没完，比如前端先合了后端还在做）、**假阴性**（活完了但判据不满足，比如分支没删）、以及上面记的 M7 反例。
- 结论写回本文档。**如果 owlet 的历史里就有判据挡不住的反例，先改设计再往下走**——改文档比改代码便宜。

> **待人点头**：只读 owlet 的 git 历史和任务文件。没点头就跳过这一层，代价是判据的正确性推迟到第 3 层才暴露，那时候改的是代码。

## 怎么算成功

- 一台没有 herdr、没有 tmux 的机器上，drover 能把队列里的任务一件接一件送进主控，人不在场时队列继续推进。
  **前提是收尾记号那条约定落地**（见完成判据那一节）。**2026-09-20 已落地**（corral 侧 `649ca22`，只改项目模板），但只对「在自己 AGENTS.md 里填了这条」的项目成立。没填的项目，这条降级成：drover 无人值守地排队、送达、盯着，**完成由人按一下键确认**——队列不会自己往下走。这不是折中，是诚实：判不出完成就别假装能自动推。
- 自举阶段连续 **5 件任务**、迁移后连续 **10 件任务**：零次「送了没到」；零次「没做完却判成做完了」；主控停下等人时，看板和通知能在 5 分钟内让人知道。
- **拆掉 drover，目标项目照常工作**（真跑一遍验证依赖方向）。收尾记号落地之后这条照样成立：那条空提交在 `git log` 里人自己也读得懂，drover 在不在都有用；模板里还明写着「不写照样能跑」。
- **corral 的源码、契约、`SKILL.md` 一行没改。** 唯一动过的是 `corral-dispatch-skill/项目AGENTS模板.md`，加了一条**可选**的收尾记号（`649ca22`，两行）。技能文件里搜不到队列、循环、drover 这类词。
  这条验收标准现在由 AGENTS.md「反依赖的四个探针」接管，四条里符合任何一条就算破了。
- 重装 drover、升级 corral，正在跑的 agent 都不受影响。
