## 从哪来

这个仓库从 herdsman（bounded-adversarial-review）clone 而来，历史全留。第一个提交 `4545f68` 砍掉了它的主题——写手 + 评审方的对抗式评审协议，以及为了管住那个昂贵过程长出来的全部外壳（findings、稳定编号、responses 格式、轮次上限、裁决文件、简报过期拦截）。

砍它的理由：证据门槛正是让评审变贵的那个东西，不是附带的。老 README 自己写着「评审通常比实现慢也更贵，因为证据要求让评审方在跑代码而非读代码」。审查这件事现在由 corral-dispatch 用更轻的方式承担（它的第 5、6 节），所以外壳没有存在理由。

**代价要认**：证据门槛没有了，误报会不会变多没有数据支撑——老仓库 143 个周期里 `precision.md` 只有 1 行填过、`escapes.md` 一条没有。「报告连续干净」和「它什么都没抓到」从内部看一模一样。这条教训直接适用于 drover 的记账：**记不出数就等于没记**。

## 定位

见 `README.md` 的三层表和 `AGENTS.md` 的硬规矩。一句话：corral 是基础设施，corral-dispatch 是内循环（主控在场），drover 是外循环（无人值守）。只能往下依赖。

内循环不是那份技能本身，是「主控会话 + 技能」。跑起来的是主控（例如 `owlet/main`）；drover 的操作对象是那个 agent，它甚至不需要知道主控读的是哪份技能。

## drover 管什么、不管什么

| 管 | 不管（内循环的事） |
|---|---|
| 队列：任务从哪来、什么顺序、插队、暂停、放弃 | 怎么拆 |
| 推进：做完自动送下一件；停住了叫醒 | 交给哪家 |
| 闸门：什么时候必须停下等人 | 几档 |
| 观察：看板 | 审不审、怎么审 |
| 记账：耗时、返工轮数、路由的实际表现 | 合不合得了 |

`bin/review-task` 今天的队列语义（add / next / done / go / pause / hold / move / edit / drop，放行模式 vs 自动模式）整套落在左栏，**一条都不改语义**，只换传输层。

## 全部动作

1. 往主控送一句话（任务正文）
2. 只读核对 git

用到的 corral 命令只有三个：`send`、`status`、`ls`。

由此：

- **叫醒送的是任务正文本身**，和人手动粘一段任务进去一模一样。老仓库的 `loop_tick` 送的是固定那句 `LOOP_PROMPT`（让写手去跑 `review-task next`）——**那是内依赖外，必须改掉**，这是「只往下依赖」能不能立住的关键。
- 主控不在（`corral status` 查不到）：不重开，挂进看板「等你」，停止送任务。
- 主控上下文会涨，不用 drover 管：Claude Code 自己压缩；任务正文每次自带，任务文件和交接文件都在磁盘上。
- `corral send` 自带退出码 7（不是 idle）和 8（30 秒内有人在接入窗口里打字），老 `loop_tick` 手写的那些判断可以删。

## 完成判据：纯 git，零解析

drover 在送出任务**之前**记下 `main` 的 sha，之后反复查三条：

1. `main` 前进了（sha 变了）；
2. 所有里程碑分支都已经是 `main` 的祖先（对每个 `git branch --list '<BRANCH_GLOB>'` 跑 `git merge-base --is-ancestor <分支> main`，`main` 自己永远不算）；
3. 验收命令退出码为 0（队列条目里写，例如 `cd backend && uv run pytest -q`）。

三条都满足才算完成。队列条目可以覆盖默认判据——人在 `queue.md` 里写这件活算完的标准，本来就是人的活。

老仓库那条「**只读核对 git 和交接目录，不听 agent 一句话**」原则原样保留，只换判据内容。

**不解析「## 主控审查」那一节**，理由见 AGENTS.md 硬规矩第 3 条。

**「它在等人」怎么识别**：主控 idle 了但判据没满足，它就停在某处等人拍板（审查复核两轮没过、和审查者有分歧、要推送、要花钱、发现设计对不上）。不需要内循环配合。

**但「idle 了」不等于「停下等人了」。** corral 契约「取值」一节写明：`idle` **只表示这一轮结束，不代表 agent 不会再动**——它可能自己开新一轮（例如后台命令跑完后自注入一条输入），契约还专门提示看 `last_input_source`（取值 `send` / `human` / `agent`）。所以这条识别要加两道：

- 看 `last_input_source`。是 `agent` 说明这一轮是它自己开的，不是在等人。
- 留一次观察间隔再下结论，别在 `idle` 刚出现那一刻就判。

还有一种情况这条识别整个失效：主控不是 Claude Code 或 Codex 时没有钩子，`corral status` 的 `state` 是 `unknown`，状态无从得知。**那时不猜**——挂进看板「等你」，让人自己去看。

**这一条最初写的是「没有残留的里程碑分支」，2026-09-20 改掉了。** 真实仓库给的反馈：jb-finetune 的 `m3/implementation` 已经合进 main 但分支没删。也就是说「分支不存在」不是普适的 git 常识，它依赖 corral-dispatch 第 7 节那套收尾纪律（`git worktree remove` + `git branch -d`），换个项目就不成立，会一直判成「没做完」（假阴性）。改成问「活合进去了吗」，删不删分支都成立，语义也更准。

**第 2 条会空真（第 2 步已挡）。** 匹配不到分支时，「所有里程碑分支都已经是 `main` 的祖先」**空真**——对空集合跑 `--is-ancestor`，一次都不跑，第 2 条直接过。而「匹配到 0 个」有三种来源，从 git 这边看一模一样：模式在配置里写错了、corral-dispatch 换了分支命名、这件活压根没建分支。任何一种都会让判据在活没干完时放行，正是止损点里写的那条「没做完却判成做完了」。**处理方式：`BRANCH_GLOB` 非空却匹配到 0 个 → 判不过；`BRANCH_GLOB` 留空 → 这条标「不适用」，不算过也不算不过。**

**原先写的 `'<前缀>-*'` 是错的，2026-09-20 改成 `BRANCH_GLOB`。** 拿两个真实项目一比就露馅：owlet 的里程碑分支是 `m8-2-backend`，jb-finetune（靶场）的是 `m3/implementation`。前缀填 `m` 得到模式 `m-*`，**两边都匹配 0 个**——也就是说照原公式写，判据在两个真实项目上都会踩空真。放宽成 `m*` 又会把 `main` 自己卷进来。两边都能用的是 `m[0-9]*`。所以配置里存的是**直接交给 `git branch --list` 的模式**，代码不再自作主张拼 `-*`，另外在代码里硬性排除 `main` 自己。

**已知待验的反例**：owlet 的 M7 出现过「合并进 main 之后主控又发起第四轮改动，改完再合一次」。也就是「合进 main」出现了两次，第一次出现时活还没真完。判据会不会提前放行，见验证计划第 2 层。

骨架全留：深色配色、「不存自己的状态，刷新等于重跑」、静态页 + `serve` 双模式、HTTP 操作、系统通知、launchd 定时。换掉的是中间那块内容。

| 现在 | 之后 |

## D1 分步

2. **完成判据**：三条的只读核对；队列条目覆盖默认判据的写法；「等人」的识别。配合验证计划第 1 层的合成测试一起写。
3. **`review-task` 换传输层**（2026-09-20 做完）：herdr 的四个调用（`agent list` / `get` / `read` / `prompt`）换成 corral 的三个（`ls` / `status` / `send`）。`HERDR_PANE_ID` 和那一整套 pane 身份核对**删掉**而不是换掉：`review-task` 现在只在 drover 这边跑，送给谁看配置里的 `MAIN_AGENT`，`.loop-wait` 里只剩原因和时间。叫醒改成送任务正文——老的往写手窗格注入「运行 review-task next，按它的输出办」是内依赖外，已经没有了；送出去的文本里现在连 `review-task` 和 `drover` 这两个词都不许出现，有测试守着。「正在调什么工具 / 这一轮多久」不再去抠 `agent read` 的输出（corral 契约明写 `read`「只作排查用，不要解析」），改用 `status` 的 `last_tool` + `turn_started`。没配 `MAIN_AGENT` 时 `next` 把任务正文打出来让人自己粘，内循环全靠人手工做的项目照样能用。

5. **安装方式和文档重写**：`install.sh` 和两个 launchd plist 已经在 `9a48774` 之后删掉了（它们会顶掉正在跑的老 herdsman），要写新的先定第 1 步那些名字和路径，Label 不能再叫 `dev.herdsman.*`。文档方面：QUICKSTART（纯步骤）和手册。老手册 5296 行已删，要重写的话从 `git show 4545f68^:docs/HANDBOOK.md` 取回参考，其中第 6c 部分（任务队列）和第 12 部分（止损点的论述）仍然有价值。

## D2 验证计划

四层，从便宜到贵，**不要跳级**：

### 第 1 层：实现对不对（仓库自带，随 D1 一起做）

用**假的 `corral` 命令** + **合成 git 仓库**，不依赖真的 corral、不依赖真的 agent、不花钱。沿用老仓库模拟 herdr 的做法。

至少要覆盖：

- 三条判据的各种组合：`main` 没动 / 分支残留 / 验收失败 / 全满足 / 验收命令本身崩了
- 送任务：主控不是 idle（退出码 7）、30 秒内有人在打字（退出码 8）、主控不存在、送达确认超时
- 队列语义：`tests/review-task.sh` 现有的 292 行改完传输层后仍要全过
- 看板渲染：`tests/review-board.sh` 现有的 752 行，删掉周期相关的，加上新的

**它证明什么**：三条都满足时返回 true。**它证明不了**：三条都满足时活真的干完了。

### 第 2 层：判据符不符合现实（一次性，离线回放）

假阳性和假阴性只有真实流程里才会露出来。做法：拿一个真跑过内循环的项目，**把它的 git 历史和任务文件当只读数据**，在每个里程碑的各个时间点上算一遍三条判据，和实际完成时刻对照。

- 全机器上唯一有真实痕迹的是 **owlet 的 M0–M8**（一个里程碑一个分支一个 worktree、任务文件在 `docs/任务/`、合并进 main）。jb-finetune 的历史用不了——它跑的是老内循环，没有里程碑分支和任务文件，判据里三条有两条无从谈起。
- 这**不需要在 owlet 上跑 drover**，只读它的历史，不碰它的 agent、不改它任何文件。
- 重点查：**假阳性**（某个时刻三条碰巧都满足但活没完，比如前端先合了后端还在做）、**假阴性**（活完了但判据不满足，比如分支没删）、以及上面记的 M7 反例。
- 结论写回本文档。**如果 owlet 的历史里就有判据挡不住的反例，先改设计再往下走**——改文档比改代码便宜。

> **待人点头**：只读 owlet 的 git 历史和任务文件。没点头就跳过这一层，代价是判据的正确性推迟到第 3 层才暴露，那时候改的是代码。

### 第 3 层：自举（drover 驱动自己的开发）

D1 做到第 3 步，drover 就已经能送任务了。此后**把 drover 剩下的活写进它自己的队列，让 drover 驱动自己的开发**。

- 天然满足「目标项目必须跑内循环」：drover 的开发本来就要用 corral-dispatch。
- 不需要动任何别的项目，也不需要等 jb-finetune 迁移。
- **一律放行模式**（每件做完等人 `go`），风险可控：drover 坏了最多是卡住自己，不会把别人的开发带沟里。
- 自举跑够 5 件任务、没有「没做完却判成做完了」，再上靶场（见下），靶场也跑顺了才进第 4 层。

### 靶场：`~/Developer/personal_projs/drover-sandbox`

2026-09-20 从 jb-finetune 本地 clone（`--no-hardlinks`），**三个远端全部删除**（公司内网 GitLab、外部 SSH、GitHub），不许 push。真的 jb-finetune 只读、不碰，它还跑在老 herdsman / herdr 上。

它比自举更接近真实：真实代码、真实测试套件、任务多样，而且出事不心疼。用法见靶场里的 `DROVER-SANDBOX.md`，核心是**回退重做**——把 `main` 回退到某个里程碑之前，让内循环重做一遍，有标准答案可以对照：既判断内循环做得对不对，也判断 drover 的判据是不是在正确的时刻触发。

`.review.conf` 没跟着 clone 过来（真仓库里是 gitignored 的），所以正在跑的 herdsman 看板扫不到它，不会干扰真 jb-finetune。加配置时别用和真仓库一样的短名。

**它验的是第 3、4 层，不是第 2 层**：clone 不改变它的历史仍然是老内循环的产物，回放算判据还是只有 owlet 能做。

### 第 4 层：jb-finetune 迁移（最后做）

jb-finetune 今天跑的是**老内循环**（写手 + 评审方 + `request-review`），不是主控 + corral-dispatch。所以这是**两次迁移**，必须拆开，一起上会分不清问题出在哪一层：

1. **换内循环**：写手 + 评审方 → 主控 + corral-dispatch。改变的是开发方式本身（任务文件、里程碑分支、worktree），和 drover 无关。手动跑两三个里程碑。
2. **接外循环**：稳定产生那些痕迹之后，drover 才接得上。先放行模式，稳了再试自动模式。

老 herdsman 仓库在第 1 步完成前保持能用，之后再决定归档还是删。

## 怎么算成功

- 一台没有 herdr、没有 tmux 的机器上，drover 能把队列里的任务一件接一件送进主控，人不在场时队列继续推进。
- 自举阶段连续 **5 件任务**、迁移后连续 **10 件任务**：零次「送了没到」；零次「没做完却判成做完了」；主控停下等人时，看板和通知能在 5 分钟内让人知道。
- **拆掉 drover，目标项目照常工作**（真跑一遍验证依赖方向）。
- corral 一行没改；corral-dispatch 的技能文件里搜不到队列、循环这类词。
- 重装 drover、升级 corral，正在跑的 agent 都不受影响。

## 止损点

- **D1 第 2 步**定不出「不解析自然语言」的完成判据：D1 结束，drover 不做，队列继续靠人手动喂。
- **验证第 2 层**发现 owlet 的真实历史里判据经常判错，且改不出可靠版本：同上。
- **验证第 3 层（自举）两周或 5 件任务**，出现以下任一条就停掉自动送任务、退回手动：
  - 一次「没做完却判成做完了」，且事后查不出原因；
  - 为了 drover 的需求不得不改 corral 或 corral-dispatch（边界划错了，先修边界再继续）；
  - 主控被送进来的任务打断正在做的事（送达时机判断失效）；
  - 你觉得盯着看板比自己手动喂任务还累。

2. **`review-map`（风险图）去留**：它和 corral-dispatch 的 `route.py` 都在判「这次改动要不要审、审多深」，但风险图是**有记忆的**（从归档证据里长出来：哪些路径出过 blocking、扇入多少、有没有测试），`route.py` 每次只拿三五句摘要问模型。三种选择：删掉、留着喂 `route.py`、单独留着当看板的一个提示。
3. **记账记什么**：老的 `precision.md` / `escapes.md` 是评审口径，没有了。换成耗时、返工轮数、路由判了什么 / 主控推翻没有。记不出数就等于没记（见「从哪来」）。
4. **要不要读任务文件开头那行「路由：…」**：读它等于依赖内循环的一个书写格式（擦边，但不要求主控多做事）。倾向「读，但降级处理」——解析失败就不显示这一项，绝不参与任何判断。不读的话这个数据只能靠人手工翻任务文件统计。
   **配套的「任务文件目录」字段跟着这一条走**：第 1 步原本要定它，但它没有别的用处，定了「读」再往 `.drover.conf` 里加（`TASK_FILE_DIR`，值如 `docs/任务`）；定「不读」就不加。
