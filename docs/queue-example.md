# queue.md 示例

这个文件本身就是一份合法的 `queue.md`：第一个 `##` 之前的内容（包括这段说明）工具不读，
下面四个任务各演示一种流程。复制到 `$REVIEW_DIR/queue.md` 删掉不要的块就能用。

**格式只有一条硬规定**：顶格的 `## 标题` 或 `## T7 标题` 开始一个任务，到下一个顶格 `## ` 之前的
所有内容都是它的正文，`review-task next` 原样发给写手。编号可省，发出时自动补；文件里的先后就是
执行顺序。正文里的小标题用 `###`，别用 `##`。

**四种流程**

| 任务 | 写法 | 规划 | 代码评审 |
|---|---|---|---|
| T21 | 不写 `流程：` | 照 AGENTS.md（没有已批准的计划就找规划者） | 每次提交后照常 |
| T22 | 正文里写「不走规划」 | 跳过 | 每次提交后照常 |
| T23 | `流程：修好再审` | 照 AGENTS.md；想跳过就再写「不走规划」 | 中间提交不审，修好后整体审一次 |
| T24 | `流程：不评审` | 跳过 | 不审；`review-task done` 把提交登记进 `docs/reviews/skipped.md` |

- `流程：` 那一行必须单独占一行，冒号中英文都行，值只能是 `不评审` 或 `修好再审`，写错或多写字就当没写（正常流程）。
- 「不走规划」只是一句普通的话，放正文哪里都行 —— 正文和人当面交代的效力一样。
- 档位以 `next` 发出时的正文为准，开始后再改不生效；要换档就 `review-task drop` 掉重新写。
- `不评审` 只用在心里有数的低风险活上；看板的已完成里会标「未评审」。

**正文建议写三件事**：目标或现象、范围（尤其是不做什么）、怎么算做完。写得越具体，规划和评审来回越少。

## T23 修复支付回调偶发超时
流程：修好再审
这次不走规划，直接做。

### 现象
支付回调偶尔超时，本地复现不了，只能在测试环境跑，每试一次都得提交部署。

### 要求
- 先加诊断日志定位，再修；修好后诊断代码删掉或降成 debug 级别
- 每次提交后照常同步测试环境

### 怎么算修好
- 测试环境连续压测 5 轮没有超时
- 报告里写清超时原因和修法
