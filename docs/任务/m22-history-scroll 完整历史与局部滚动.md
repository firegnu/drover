### 性能结果

每格独立执行三次，单位为秒，表中为 `task_view` 总时间中位数；耗时不含合成仓库创建。Git 调用次数在三次测量中一致。

| 路由目录 | 历史总数 | 原截取：显示5条 / git次数 / 秒 | 临时取消截取：显示全部 / git次数 / 秒 |
|---|---:|---|---|
| 未配置 | 5 | 5 / 5 / 0.031952 | 5 / 5 / 0.031839 |
| 未配置 | 300 | 5 / 5 / 0.045139 | 300 / 300 / 2.052592 |
| 300份任务文件 | 5 | 5 / 5 / 0.029951 | 5 / 5 / 0.029923 |
| 300份任务文件 | 300 | 5 / 5 / 0.043211 | 300 / 300 / 2.177290 |

有路由目录、300 条、取消截取的三次总耗时为 2.172858、2.177290、2.192606 秒（按大小列出），相对同样 300 条的基线约 50 倍。细分中位数：

- `git`：300 次，2.086445 秒，约占总时间 96%；主因是逐条同步 Git 子进程。
- `task_route`：300 次，0.083194 秒，其中 `os.listdir` 300 次 / 0.039481 秒，`route_line` 300 次 / 0.020145 秒。目录扫描及文件读取包含在路由总时间内，不能重复相加。
- 无路由目录时仍需 2.052592 秒，其中 Git 2.042473 秒，排除路由作为主要瓶颈。

这是单项目、仅历史数据阶段的耗时，不是完整 collect、VM、draw 或设备输入延迟测量。根据现有 tui 的同步刷新路径，历史查询期间无法读取下一次输入，因此即使空闲周期仍是30秒，r/周期/缩放刷新时增加约两秒停顿也已明显；多项目还会累加。不以「以后优化」略过这项门槛。
