## 要做的

详情区（`draw()` 里 `detail_lines()` 那一段）现在超出窗口高度就截断，末行写「… 还有 N 行，窗口再高些」。队列一长就不够用了。让它能滚。

### 1. 滚动本身

- 加翻页按键。建议 `PgDn` / `PgUp`（`curses.KEY_NPAGE` / `curses.KEY_PPAGE`）；要不要再加行级滚动或 Home/End 你定，但**别占用已经有含义的键**：`j` `k` `↑` `↓`（选项目）、`g` `n` `p` `a` `l` `r` `q`。
- 到顶、到底都要夹住，不许滚出空白。
- **切换选中的项目时偏移归零**——换了个项目还停在第 30 行是错的。
- 窗口变矮、或者内容变短（下一次刷新行数少了）之后，偏移要重新夹住，不能停在越界的位置。
- 末行那句提示跟着改：现在它说「窗口再高些」，有滚动之后应该告诉人**还能往下翻**（措辞你定）。顶部也被滚掉时最好有个对应的提示。

### 2. 偏移量放哪：这件活唯一需要你拿主意的地方

偏移量是**进程内的 UI 状态**，存在 `draw()` / `key_action()` 共用的那个 `state` 字典里，**绝不落盘**（硬约束：看板不存自己的状态，刷新等于重跑）。

真正的张力在这里，请正面处理，别绕开：

> `key_action` 是纯函数，可算新偏移要夹住就得知道「详情区一共几行」和「一屏放得下几行」——这两个数只有 `draw()` 在拿到窗口尺寸之后才知道。

几条路都想得到，各有代价：把夹住挪进 `draw()`（`draw` 就不再是「只有排版没有判断」了）；让 `draw()` 把上一次的行数/可视高度写回 `state`，`key_action` 读它（`draw` 有了副作用，且第一帧没有这个数）；`key_action` 只返回相对量、由 `tui()` 夹住（判断散进了那层最难测的代码）。

**你选哪条都可以，但要满足两条硬要求**：

- `key_action(k, pv, state)` 和 `draw(stdscr, vm, state)` 的**签名一个字不能改**（测试和别的调用方按位置传参）。`state` 字典里加键是可以的。
- 新加的滚动逻辑**必须能在不开 curses 的情况下断言**——和现在 `key_action` 一样喂参数就能验。如果你的方案把夹住放进了 `draw()`，那就把「夹住」本身拆成一个纯函数单独测。

把选择和被否掉的方案各一句话写进任务文件末尾的「## 实现时的取舍」，并在回复里列出来。
