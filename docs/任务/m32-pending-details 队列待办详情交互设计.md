### 做法：一张整屏的「待办详情」页

- **进入**：看板上按 `u`，打开当前选中项目的待办详情页，默认显示第 1 件（▸ Next）。没有待办时不打开，消息栏显示 `No pending tasks`。
- **选择**：页内用 ↑↓ / jk 切到上一件或下一件待办（到头就停），顶栏显示 `Up next 2/3`。在这张页里 ↑↓ 不切项目。
- **看内容**：先显示队列条目的正文原文。正文里有 `任务文件：` 这一行的，下面接着显示那份文件的全文；文件找不到就写 `Task file not found: <路径>`，没有这一行就不显示这一节。内容按列宽换行，PgUp/PgDn 翻页，带位置条和 `PgUp↑ PgDn↓` 提示，写法同帮助页。
- **返回**：按 Esc 回看板。项目选择、详情翻页位置、正文和历史的滚动位置都和进入前一样（跟 `?` 页一样，只写自己的 `pending_*` 状态）。
- **页内安全**：g/n/p/a/l 和鼠标一律不生效，避免看着待办时误按 `n` 发出任务。r 和 30 秒自动刷新照常重跑，q 照常退出。
- **刷新时正在看的那件**：按编号记住（没编号就按标题）。刷新后它已经发出去或被删了，就停在原来那个序号上，由顶栏编号和标题显示换成了哪一件，不另外提示。
- **只读**：任务文件的路径照现有 `task_files` 的规则，相对仓库主检出目录解析，只读取、不写入。刷新等于重跑：读文件放在 view_model 那一层，而且只读正文里显式引用了的那几份，draw 仍然只排版。

### 需要你决定的取舍

1. **入口键**：推荐 `u`，对应栏目名 Up next，跟现有单字母键一个风格。另一个选项是 Enter，更符合「打开」的直觉，但看板上并没有光标停在待办上，按 Enter 打开的是什么不够直观。
2. **怎么找任务单**：推荐只认正文里显式写的 `任务文件：` 这一行，贴你原话里的「正文引用了任务文件」。另一个选项是再加上 `TASK_FILE_DIR` 按标题前缀匹配（路由行现在就是这么找的），能覆盖没写那一行的条目，但同一前缀下常常有交叉审查、审查意见等好几份文件，而且待办还没派出去时任务单多半还不存在，容易显示错文件或者显示一串文件。
3. **滚动方式**：推荐只用 PgUp/PgDn，和帮助页一致。另一个选项是支持鼠标滚轮，读长任务单更顺手，但要为这张页单独做一套命中区域和偏移处理，实现量明显变大。
4. **怎么让人发现这个功能**：推荐只在 `?` 帮助页加一行 `u  View pending tasks and their task files`，底栏不动，跟 T19 不在底栏加 `? Help` 的决定一致。另一个选项是在底栏按键提示里也加上 `u up next`，好找，但会改动现有底栏的排版。
